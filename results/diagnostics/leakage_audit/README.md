# Feature-level leakage audit (2026-09-17)

Generated by `scripts/leakage_feature_audit.py` (schema.csv, features.csv) and
`scripts/feature_names.py` (feature_names.csv); raw-CSV checks were run inline and
are summarised here. Trigger: the CSE-CIC-IDS2018 `Src Port` finding.

## Verdicts

| Dataset | Verdict | Evidence |
|---|---|---|
| CSE-CIC-IDS2018 | **Contaminated** (padding artifact) | `Flow ID`, `Src IP`, `Src Port`, `Dst IP` exist only in `02-20-2018.csv` (schema.csv). Loader zero-pads them; the three string columns become all-zero, `Src Port` (f80) is nonzero on exactly the 02-20 rows (48%) and never on r2l/u2r. |
| Edge-IIoTset | **Contaminated** (serialization artifact) | Seven object columns hold a zero placeholder spelled `0` or `0.0` depending on the source capture. `mqtt.topic`, `mqtt.protoname`, `mqtt.conack.flags`, `dns.qry.name.len`: Normal always `0`, every attack `0.0` (binary label fully determined). `http.request.version` / `http.request.method`: `0` for {DDoS_HTTP, MITM, Password, SQL_injection, Uploading, Vulnerability_scanner, XSS}, `0.0` for the rest. `http.referer`: `0` for {Vulnerability_scanner, XSS} (+DDoS_HTTP), and 185 rows hold a Shellshock payload string. The loader one-hot encodes the raw strings, so each spelling is a feature (NMI up to 0.48). |
| ISCX-IDS2012 | Judgement call (not a bug) | `direction` (IP-locality, L2L/L2R/R2L/R2R) is kept and one-hot encoded: L2R is 99.98% normal, attacks are ~99% L2L or R2L. A documented dataset field, but derived from addresses, while Sec. V-B says addresses are removed. |
| KDD Cup 99, NSL-KDD, UNSW-NB15, CIC-IDS2017, CTU-13, TON_IoT, CICIoMT2024, CICIoT2023 | No artifact found at this level | Identical schema across source files; every class-excluding indicator is protocol/service semantics (e.g. r2l over TCP, ICMP floods without TCP flags). |

## Scope of the screen

Layer B tests only the zero/non-zero ("off its floor") indicator of each
preprocessed feature. Value-level shortcuts (a specific TTL, port or window size)
are not detected; the UNSW-NB15 `sttl`/`ct_state_ttl` shortcut reported in the
literature is of that kind and is not ruled out by this audit.

## Follow-up checks (2026-09-17, same session)

* `0`/`0.0` split elsewhere: no other dataset has two spellings of the same
  numeric value among its one-hot columns (feature_names.csv scan). Edge-IIoTset only.
* Edge-IIoTset row integrity (DNN-EdgeIIoT-dataset.csv, and identically in the
  per-attack CSVs under `Attack traffic/`, so it originates in the published
  extraction, not in the merge):
  * **DDoS_UDP (all 121,568 rows) is shifted one column left**: `frame.time` holds
    the spoofed source IP, `ip.src_host` the victim 192.168.0.128, `ip.dst_host` 0,
    and the UDP source port sits under `tcp.srcport` while `udp.port` is 0. Every
    other class has a timestamp in `frame.time`. The class therefore has a
    label-specific column layout.
  * **MITM (all 1,214 rows) is corrupted differently**: `frame.time` is a small
    number (e.g. `6.0`); 227 rows carry hostnames under `tcp.srcport`, a port under
    `udp.port`, and non-0/1 values in `dns.qry.qu`.
  * **1,845 Normal DNS rows are shifted one column right** from `udp.port` on
    (hostname under `dns.qry.name.len`, its length under `dns.qry.qu`, qtype under
    `dns.retransmission`). Detectable by `dns.qry.qu` not in {0,1}.
  * `mqtt.conack.flags = 0x00000000` (83,017 Normal MQTT rows) is a hex rendering,
    not a shift; parse as hex.
  * `ip.src_host = 0` on 285,604 rows (mostly Normal) is consistent with non-IP
    frames and is dropped as a feature anyway.

## Edge-IIoTset repair: verification (2026-09-17)

Repair: `src/data/repair.py`; tests: `python -m unittest tests.test_repair` (15 pass).
Verification: `scripts/verify_edgeiiot_repair.py` (tshark 4.2.2, first occurrence of
multi-valued fields) -> `edgeiiot_repair_verification.{json,csv}`. Every decoded
row, not a sample, was matched to its packet by (ip.src_host, ip.dst_host,
udp.port, udp.stream) and compared on all 60 fields other than `frame.time`.

| Layout | Rows | Matched | All 60 fields match | Fields the published CSV gets wrong (published match rate) |
|---|---|---|---|---|
| decoded_udp_flood (DDoS_UDP) | 110,035 | 110,035 (unique packet) | 110,035 | ip.src_host, ip.dst_host, tcp.srcport, udp.port (0% each) |
| decoded_icmp_reply (DDoS_UDP) | 11,533 | 11,533 (unique packet) | 11,533 | ip.src_host, arp.dst.proto_ipv4, icmp.checksum, icmp.seq_le, udp.port, udp.stream, dns.qry.name (0% each) |
| decoded_normal_udp (Normal) | 2,227 | 2,227 (flow; median 4 candidate packets, max 358) | 2,227 | udp.stream, udp.time_delta (0%); dns.qry.name 6.7%; dns.qry.name.len / qu / retransmission 17.2%; dns.qry.type 17.6% |

Per-field repaired match rate is 100% for every field in every layout. For Normal
UDP several packets share a flow key, so a row counts as verified when some packet
of its flow matches it on every field. Comparison treats tshark 4.x `True/False`
as the published `1/0`; before that normalisation 59 Normal rows appeared to fail
on `dns.qry.qu` / `dns.retransmission` only.

Not recoverable / filled: `frame.time` for all DDoS_UDP rows (absent from the
source CSV; the date is truncated for every row anyway, and the column is not a
feature). Upstream-truncated trailing fields (mbtcp.trans_id and mbtcp.unit_id for
ICMP replies, mbtcp.unit_id for Normal UDP) are filled with 0 and match the pcap
(empty) on every row.

Layout-only detector (`layout_detector_control.json`): F1 1.000 published, 0.9994
repaired, 0.701 on CICIoT2023. The repair does not move it, so it does not isolate
the artifact and is not used as evidence.
