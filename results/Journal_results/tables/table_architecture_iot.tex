\caption{4-way model anatomy per dataset over the IoT, IIoT, and IoMT intrusion detection datasets: class count, network architecture (layer widths), total parameters, and hidden-layer spikes generated per sample (mean$_{\pm\text{std}}$ over 5 seeds). DNN-Tree is the dense iso-architecture twin of Tree-to-Spike (identical widths and parameters, ReLU instead of LIF), so it emits no spikes. Architecture strings use the seed-42 tree-guided encoder width; the encoder (and hence Tree-to-Spike/DNN-Tree input width and parameter count) varies slightly across seeds with the teacher refit, so parameters are the across-seed mean. TASNN: Tr = transformer encoder (d\_model$\times$layers), STC = spatio-temporal conv channels, then the LIF core. $^\ddagger$For the dense DNN-Tree the cell reports \emph{activated neurons} per sample (nonzero hidden ReLU outputs, measured on the test set of the int8-quantised model): a ReLU neuron does work once per input, whereas a spiking neuron does work once per emitted spike, so the two counts are the per-paradigm analogs but not interchangeable (spikes accumulate over $T$ timesteps). \textbf{TTFS} = mean encoder time-to-first-spike over spiking channels $\times$ test samples, shown as steps$/T$ (Vanilla SNN: latency code over raw features, sub-threshold inputs never fire; Tree-to-Spike: tree-guided code; DNN-Tree and TASNN have no TTFS input code). Note TTFS is the \emph{mean arrival time of all emitted spikes} (the code's centre of mass), not the first-arrival time: under latency coding the most informative (highest-level) channels fire first, and the first spike arrives at $t \approx 0$ for virtually every sample, which is why the early-exit step can be far smaller than the mean TTFS. \textbf{Exit} = mean confidence-triggered early-exit timestep$/T$ (DNN-Tree is one-shot; TASNN has no early exit). \textbf{Rel.\,E} = compute energy relative to Tree-to-Spike on the same dataset ($n\times$ = $n$ times our energy; $^\dagger$TASNN analytic). \textbf{Storage} = projected deployment footprint at FP32\,/\,int8, in KB: model weights (4 / 1 bytes per parameter) plus, for the models that use the tree-guided encoder, the frozen encoder tables it must ship with ($^{\S}$Tree-to-Spike and its DNN-Tree twin: split thresholds at 4 B plus a 3 B channel-map entry each; the Vanilla SNN latency code and TASNN store no tables). These are analytical projections from parameter and table counts, not measured serialized artifacts: our int8 stage is a per-tensor fake-quant stand-in that quantizes Linear weights while retaining fp32 tensors, so the int8 column is a lower bound (biases and encoder thresholds remain fp32).}
